# ⚙️ کران فولاد — ربات اخبار بازار آهن و فولاد

این پروژه همان ربات قبلی است که روی GitHub Actions اجرا می‌شود، اما منطق دریافت،
فیلتر، تاریخ، Gemini، Telegram و حافظه دائمی آن اصلاح شده است.

## ساختار فایل‌ها

```text
steel-news-bot/
├── steel_news_bot.py
├── requirements.txt
├── sent_links.json
└── .github/
    └── workflows/
        └── steel-news.yml
```

> فایل `steel-news.yml` در ریشه پروژه لازم نیست. فقط فایل داخل
> `.github/workflows/steel-news.yml` توسط GitHub Actions اجرا می‌شود.

---

## رفتار نسخه جدید

### 1. فقط اخبار همان روز

ربات تاریخ انتشار واقعی خبر را با منطقه زمانی:

`Asia/Tehran`

بررسی می‌کند.

اگر امروز مثلاً ۱۴۰۵/۰۷/۰۲ باشد:

- خبر منتشرشده امروز → بررسی و در صورت مرتبط‌بودن ارسال می‌شود.
- خبر دیروز → ارسال نمی‌شود.
- خبر هفته قبل → ارسال نمی‌شود.
- خبر بدون تاریخ معتبر → ارسال نمی‌شود.

بنابراین اگر RSS یک سایت ناگهان ۱۰۰ خبر قدیمی را برگرداند، ربات آن‌ها را به کانال نمی‌فرستد.

### 2. اجرای هر ۵ دقیقه

Workflow هر ۵ دقیقه RSSها را بررسی می‌کند.

زمان‌بندی GitHub بر اساس UTC است، اما تشخیص «امروز» داخل Python با ساعت ایران انجام می‌شود.

> زمان اجرای Scheduled Workflow در GitHub تضمین‌شده و دقیقاً در همان دقیقه نیست؛
> بنابراین «هر ۵ دقیقه» به معنی بررسی با این فاصله است، نه تضمین اجرای دقیق در
> ثانیه یا دقیقه مشخص.

### 3. حافظه دائمی

`sent_links.json` حافظه دائمی ربات است.

بعد از اینکه Telegram با موفقیت یک خبر را دریافت کرد، آن خبر در state ثبت می‌شود.

در اجرای بعدی:

```text
خبر قبلاً ارسال شده؟ → بله → رد شود
خبر قبلاً ارسال شده؟ → خیر → بررسی شود
```

این state بعد از اجرا توسط GitHub Actions در Repository ذخیره می‌شود.

بنابراین اجرای جدید GitHub از صفر شروع نمی‌کند.

### 4. اگر ربات هنگ کند چه می‌شود؟

اگر Gemini برای یک خبر خطا بدهد، آن خبر به عنوان ارسال‌شده ثبت نمی‌شود.

اگر Telegram ارسال را قبول نکند، آن خبر هم ثبت نمی‌شود.

پس اجرای بعدی دوباره همان خبر را امتحان می‌کند.

برعکس، اگر Telegram موفق شود، همان لحظه خبر در state ثبت می‌شود.

### 5. جلوگیری از اجرای هم‌زمان

Workflow دارای `concurrency` است.

اگر یک اجرای قبلی هنوز تمام نشده باشد، اجرای بعدی هم‌زمان با آن شروع نمی‌شود.
این موضوع از خراب‌شدن یا overwrite شدن state جلوگیری می‌کند.

## فیلتر تخصصی فولاد

فقط وجود کلمه «آهن» باعث انتشار خبر نمی‌شود.

ابتدا یک فیلتر سریع کلمات تخصصی مثل:

- فولاد
- میلگرد
- تیرآهن
- شمش
- بیلت
- اسلب
- ورق فولادی
- HRC
- CRC
- گندله
- کنسانتره
- آهن اسفنجی
- قراضه
- سنگ‌آهن
- بورس کالا
- تولید فولاد
- صادرات و واردات فولاد

اجرا می‌شود.

بعد Gemini تشخیص می‌دهد که خبر واقعاً به صنعت فولاد مرتبط است یا خیر.

خبرهایی مثل «آهن موجود در بدن» یا موضوعات نامرتبط با صنعت فولاد حذف می‌شوند.

## Gemini

برای هر خبر فقط یک درخواست Gemini ارسال می‌شود.

Gemini در همان یک درخواست این موارد را تولید می‌کند:

- مرتبط بودن خبر
- تشخیص خبر واقعی یا محتوای غیرخبری
- دسته‌بندی
- اهمیت
- تیتر فارسی
- خلاصه فارسی
- تحلیل کوتاه
- اثر احتمالی بازار

اگر Gemini خطا کند، خبر منتشر نمی‌شود تا اجرای بعدی دوباره تلاش کند.

## قالب پیام Telegram

پیام نهایی تقریباً به این شکل خواهد بود:

```text
🏭 تیتر حرفه‌ای خبر

📌 خلاصه خبر:
خلاصه فارسی کوتاه...

📊 تحلیل کوتاه:
تحلیل اقتصادی/بازاری کوتاه...

🎯 اثر احتمالی بر بازار:
📈 افزایشی

📰 منبع: مشاهده خبر
(نام منبع)

⚙️ کران فولاد
```

لینک اصلی پشت عبارت «مشاهده خبر» قرار می‌گیرد و URL طولانی در پیام دیده نمی‌شود.

## Secrets موردنیاز GitHub

در:

`Settings → Secrets and variables → Actions`

این موارد را تنظیم کنید:

### الزامی

```text
TELEGRAM_BOT_TOKEN
TELEGRAM_CHAT_ID
GEMINI_API_KEY
```

### اختیاری

```text
TELEGRAM_ADMIN_CHAT_ID
GEMINI_MODEL
```

اگر `TELEGRAM_ADMIN_CHAT_ID` تنظیم نشود، هشدار خطا به همان
`TELEGRAM_CHAT_ID` ارسال می‌شود.

اگر `GEMINI_MODEL` تنظیم نشود، مدل پیش‌فرض:

```text
gemini-2.5-flash-lite
```

استفاده می‌شود.

## اولین اجرای نسخه جدید

نگران `sent_links.json` نباشید.

نسخه جدید فرمت قبلی فایل را هم می‌خواند و لینک‌های قبلی را حفظ می‌کند.

بنابراین بعد از جایگزینی فایل‌ها:

- اخبار قدیمی دوباره ارسال نمی‌شوند.
- خبرهای مربوط به امروز بررسی می‌شوند.
- خبرهای جدید امروز در صورت تأیید منتشر می‌شوند.

## نکته مهم درباره «تا ابد»

هیچ منطق تاریخ روزانه‌ای بر اساس پاک‌کردن state در نیمه‌شب وجود ندارد.

یعنی وقتی روز عوض می‌شود:

```text
امروز → ۱۴۰۵/۰۷/۰۲
          ↓
فقط اخبار ۱۴۰۵/۰۷/۰۲

نیمه‌شب
          ↓

امروز → ۱۴۰۵/۰۷/۰۳
          ↓
فقط اخبار ۱۴۰۵/۰۷/۰۳
```

اما حافظه خبرهای قبلی پاک نمی‌شود.

پس خبر ۲ مهر اگر در ۱۰ مهر دوباره در RSS ظاهر شود، دوباره منتشر نخواهد شد.

## اجرای دستی

از GitHub:

`Actions → Steel News Bot → Run workflow`

می‌توانید اجرای دستی انجام دهید.

حتی در اجرای دستی نیز قانون «فقط اخبار امروز» برقرار است.
اجرای دستی باعث ارسال آرشیو قدیمی نمی‌شود.
